Controlled vs Uncontrolled

Understand who owns a form input's value — React state or the browser DOM — and see the difference in re-rendering with a live experiment.

01 • Introduction

Who owns the input's value?

In normal HTML, the browser keeps the input value inside the DOM. React gives us two ways to manage it: React can become the single source of truth, or the DOM can keep the value and React can read it when needed.

Controlled Component

React state is the single source of truth.

useState value onChange
  • Every change updates state.
  • State changes cause a component render.
  • The input displays the state value.

Uncontrolled Component

The DOM itself holds the input's current value.

useRef ref defaultValue
  • Typing changes the DOM value directly.
  • Typing itself does not update React state.
  • A ref reads the value when required.

03 • Controlled

Controlled Component

If the input value comes from useState and changes through onChange, React controls the input.

User types
↓
onChange fires
↓
setName(value)
↓
Re-render
↓
value={name}

React Example

import { useState } from "react";

function NameForm() {
  const [name, setName] = useState("");

  const onSubmit = (e) => {
    e.preventDefault();
    console.log(name);
  };

  return (
    <form onSubmit={onSubmit}>
      <input
        value={name}
        onChange={(e) =>
          setName(e.target.value)
        }
      />
      <button>Submit</button>
    </form>
  );
}

What happens?

  1. User types a character.
  2. onChange runs.
  3. setName() updates state.
  4. React renders the component again.
  5. value={name} displays the latest state.
Exam line: If the value comes from useState, it is a controlled component.
04 • Uncontrolled

Uncontrolled Component

The browser/DOM keeps the current input value. React uses a ref to read that value when needed, usually during submission.

User types
↓
DOM stores value
↓
No state update
↓
No render from typing
↓
ref.current.value

React Example

import { useRef } from "react";

function NameForm() {
  const nameRef = useRef(null);

  const onSubmit = (e) => {
    e.preventDefault();
    console.log(nameRef.current.value);
  };

  return (
    <form onSubmit={onSubmit}>
      <input
        ref={nameRef}
        defaultValue=""
      />
      <button>Submit</button>
    </form>
  );
}

What happens?

  1. User types into the input.
  2. The DOM stores the current value.
  3. No React state is updated by typing.
  4. React does not re-render because of the typing.
  5. On submit, the ref reads the current value.
Exam line: If the value is accessed through a ref instead of React state, it is generally an uncontrolled component.
05 • Key Detail

value vs defaultValue

value → Controlled

<input
  value={name}
  onChange={e =>
    setName(e.target.value)
  }
/>
  • value comes from React state.
  • onChange keeps state updated.
  • React controls what is displayed.

defaultValue → Uncontrolled

<input
  ref={nameRef}
  defaultValue=""
/>
  • defaultValue provides the initial value.
  • The DOM owns the current value afterwards.
  • ref.current.value reads it later.
Remember: Do not normally mix value and defaultValue on the same input. A controlled input with value but no onChange is effectively read-only.

07 • Practical Use

Where can we use them?

Controlled — examples

  • Live search: filter results as the user types.
  • Login/signup: show validation messages immediately.
  • Multi-step forms: share form state between steps.
  • Character counter: display remaining characters live.

Uncontrolled — examples

  • File input: file inputs are handled as uncontrolled inputs.
  • Simple forms: read values only when submitting.
  • DOM-based libraries: useful when another library owns the DOM.

Key Takeaway

Controlled: React owns the value.
Uncontrolled: DOM owns the value.

Choose based on what your form needs: live state, validation and synchronization versus simpler DOM-based value handling.

08 • Viva / Exam Preparation

Quick questions & answers

1. What is a controlled component?
A form input whose value is controlled by React state, usually using useState, value, and onChange.
2. What is an uncontrolled component?
A form input whose current value is maintained by the DOM and accessed from React using a ref.
3. Which hook is commonly used for controlled inputs?
useState().
4. Which hook is commonly used for uncontrolled inputs?
useRef().
5. Does uncontrolled typing cause a React render?
Not by itself. Changing the DOM input value does not update React state.
6. Why does a controlled input usually re-render?
Typing triggers onChange, which calls a state setter such as setName(), causing React to render with the new state.
7. What is the difference between value and defaultValue?
value is used to control the current value from state; defaultValue supplies an initial value for an uncontrolled input.
8. What is the easiest way to remember?
Controlled = React controls. Uncontrolled = DOM controls.

Final 10-second explanation

“In a controlled component, React state is the single source of truth. Every input change updates state and normally causes a re-render. In an uncontrolled component, the DOM stores the value, so typing itself does not cause a React re-render. We use a ref to read the value when needed.”
